# VarashWorks

Майбутній сервіс пошуку майстрів Вараша та навколишніх сіл. **VarashWorks — робоча назва.** Зараз створено локальний каркас: сторінки й статичні UI-компоненти, між якими можна переходити. Дані, фільтрацію, форми й решту функціональності ти реалізовуватимеш самостійно з поясненнями та допомогою.

Будуємо невеликими кроками: спочатку розуміємо зміну, потім пишемо код і перевіряємо результат. Візуальний напрям — білий фон, синій акцент, читабельна типографіка, чіткі картки й фільтри. Підхід **mobile-first**: базовий CSS для телефона, розширення через `min-width` для більших екранів. Кожну наступну зміну спочатку перевіряємо на ширині 320–390 px, потім на планшеті й комп’ютері; для елементів керування передбачаємо помітний фокус і, де доречно, область натискання від 44 × 44 px.

## Запуск

Потрібні Node.js **24.19.0** (див. `.nvmrc`) і npm. Відкрий термінал у папці проєкту:

```sh
npm ci
npm run dev
```

Відкрий [localhost:3000](http://localhost:3000). Зміни у файлах одразу відображатимуться в браузері. Щоб зупинити сервер, натисни `Ctrl+C` у терміналі.

| Команда          | Для чого                                           |
| ---------------- | -------------------------------------------------- |
| `npm ci`         | Встановити залежності точно за `package-lock.json` |
| `npm run dev`    | Запустити локальну розробку                        |
| `npm run check`  | Перевірити Biome, типи TypeScript і форматування   |
| `npm run build`  | Створити виробничу збірку                          |
| `npm run start`  | Запустити вже створену збірку локально             |
| `npm run format` | Автоматично відформатувати файли                   |

`check` включає `next typegen` та `tsc --noEmit`: спочатку Next.js генерує потрібні типи маршрутів, потім TypeScript перевіряє код без створення JavaScript-файлів. Biome шукає проблеми в коді, JSX і доступності через рекомендовані правила React та Next.js. Команда `lint` виконує `biome lint . --error-on-warnings`. Prettier відповідає за форматування всіх файлів; форматування й assist у Biome вимкнені. Автоматичний lint не гарантує відповідності WCAG — інтерфейс також перевіряємо вручну.

Файл `.github/workflows/ci.yml` запускає `npm ci`, `npm run check` і `npm run build` у GitHub після push або pull request. Це CI — автоматична перевірка змін у репозиторії. Наявність файлу й локальні перевірки ще не означають, що віддалений запуск відбувся.

## Що де лежить

| Файл                                                 | Призначення                                                |
| ---------------------------------------------------- | ---------------------------------------------------------- |
| `src/app/layout.tsx`                                 | Спільний HTML-каркас, мова документа й метадані            |
| `src/app/page.tsx`                                   | Сторінка адреси `/`                                        |
| `src/app/page.module.css`                            | Локальні стилі стартової сторінки                          |
| `src/app/masters/page.tsx`                           | Статична заготовка каталогу                                |
| `src/app/masters/[slug]/page.tsx`                    | Заготовка майбутнього профілю; параметр ще не обробляється |
| `src/app/request/page.tsx`                           | Заготовка сторінки заявки                                  |
| `src/app/for-masters/page.tsx`                       | Заготовка сторінки для майстрів                            |
| `src/app/not-found.tsx`                              | Сторінка для відсутнього маршруту                          |
| `src/app/globals.css`                                | Базові стилі та спільні CSS-змінні                         |
| `src/app/robots.ts`                                  | Правила для пошукових роботів                              |
| `src/modules/catalog/components/master-card.tsx`     | Статична заготовка картки майстра                          |
| `src/modules/catalog/components/catalog-filters.tsx` | Заготовка області майбутніх фільтрів                       |
| `src/modules/catalog/components/catalog-results.tsx` | Заготовка області майбутніх результатів                    |
| `src/shared/config/site.ts`                          | Назва й опис сайту в одному місці                          |
| `src/shared/ui/site-header.tsx`, `site-footer.tsx`   | Спільні шапка й підвал сторінок                            |
| Файли `*.module.css` поруч із компонентами           | Стилі відповідної сторінки або компонента                  |
| `package.json`                                       | Команди проєкту й залежності                               |
| `package-lock.json`                                  | Точні версії встановлюваних залежностей                    |
| `biome.json`                                         | Правила перевірки коду та JSX                              |
| `.github/workflows/ci.yml`                           | Автоматичні перевірки в GitHub                             |
| `docs/product-plan.md`                               | Повний продуктовий план                                    |
| `docs/roadmap.md`                                    | Поточний крок і наступні невеликі задачі                   |
| `docs/decisions/0001-foundation.md`                  | Причини вибору технічної основи                            |
| `docs/lessons/01-initialization.md`                  | Перший урок на 5–10 хвилин                                 |
| `docs/lessons/02-catalog.md`                         | План першої самостійної реалізації без готового розв’язку  |

Основа: **Next.js 16.4.2** з App Router, **React 19.3.1**, **TypeScript 6.0.3** у строгому режимі, CSS Modules, **Biome 2.5.15** і **Prettier 3.9.10**. Використовуємо сумісні зафіксовані стабільні версії; оновлення перевіряємо разом із залежностями.

Компоненти поки серверні: для статичного каркаса не потрібні `"use client"` та хуки стану. Для навчальних сторінок задано `noindex`; повернемося до індексації перед публікацією справжнього вмісту.

Почни з [першого уроку](docs/lessons/01-initialization.md), потім відкрий [наступну задачу](docs/lessons/02-catalog.md) і звірся з [дорожньою картою](docs/roadmap.md). База даних, підтвердження телефону й розгортання з’являться на наступних етапах за продуктовим планом.

Домовленість про роботу: асистент готує каркас та інструменти, ти пишеш функціональність. Нові інструменти фронтенду й бекенду розбираємо перед використанням. Наступні зміни робимо малими кроками: задача → твоя спроба → пояснення й перевірка.

Коли робити коміт, як його назвати й як підготувати зміни — у [пам’ятці Git](docs/git-workflow.md). Перший коміт зробимо після завершення поточної картки та перевірок; далі кожна невелика завершена зміна матиме свій зрозумілий коміт.
