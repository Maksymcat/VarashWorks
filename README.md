# VarashWorks

Сервіс пошуку майстрів Вараша та навколишніх сіл на етапі прототипу. **VarashWorks — робоча назва.** Реалізовано каркас сторінок, каталог із трьома вигаданими записами та пошук запису за `slug` у модулі даних. Фільтри, персональні сторінки майстрів, заявки й бекенд ще не реалізовані.

Візуальний напрям — білий фон, синій акцент, читабельна типографіка, чіткі картки й фільтри. Підхід **mobile-first**: базовий CSS для телефона, розширення через `min-width` для більших екранів. Зміни інтерфейсу спочатку перевіряються на ширині 320–390 px, потім на планшеті й комп’ютері; для елементів керування передбачено помітний фокус і, де доречно, область натискання від 44 × 44 px.

## Запуск

Потрібні Node.js **24.19.0** (див. `.nvmrc`) і npm. Відкрий термінал у папці проєкту:

```sh
npm ci
npm run dev
```

Відкрий [localhost:3000](http://localhost:3000). Зміни у файлах одразу відображатимуться в браузері. Щоб зупинити сервер, натисни `Ctrl+C` у терміналі.

| Команда          | Для чого                                           |
| ---------------- | -------------------------------------------------- |
| `npm ci`         | Встановити залежності точно за `package-lock.json` |
| `npm run dev`    | Запустити локальну розробку                        |
| `npm run check`  | Перевірити Biome, типи TypeScript і форматування   |
| `npm run build`  | Створити виробничу збірку                          |
| `npm run start`  | Запустити вже створену збірку локально             |
| `npm run format` | Автоматично відформатувати файли                   |

`check` включає `next typegen` та `tsc --noEmit`: спочатку Next.js генерує потрібні типи маршрутів, потім TypeScript перевіряє код без створення JavaScript-файлів. Biome шукає проблеми в коді, JSX і доступності через рекомендовані правила React та Next.js. Команда `lint` виконує `biome lint . --error-on-warnings`. Prettier відповідає за форматування всіх файлів; форматування й assist у Biome вимкнені. Автоматичний lint не гарантує відповідності WCAG — інтерфейс також перевіряємо вручну.

Файл `.github/workflows/ci.yml` запускає `npm ci`, `npm run check` і `npm run build` у GitHub після push або pull request. Це CI — автоматична перевірка змін у репозиторії. Наявність файлу й локальні перевірки ще не означають, що віддалений запуск відбувся.

Основа: **Next.js 16.4.2** з App Router, **React 19.3.1**, **TypeScript 6.0.3** у строгому режимі, CSS Modules, **Biome 2.5.15** і **Prettier 3.9.10**. Використовуємо сумісні зафіксовані стабільні версії; оновлення перевіряємо разом із залежностями.

Компоненти поки серверні. До запуску реального каталогу для сторінок задано `noindex`, а `robots.txt` забороняє обхід. Ці налаштування не є захистом доступу. Індексація потребуватиме окремого налаштування перед публікацією перевіреного вмісту.

## Поточні обмеження

Усі записи каталогу вигадані й позначені як демо. Заголовки карток і посилання профілів ще потребують завершення; сторінка `/masters/[slug]` поки показує одну заготовку й не викликає функцію пошуку. Стан без результатів, обробка відсутнього профілю, база даних, авторизація, SMS і приймання заявок не підключені.

## Робота зі змінами

Зміни виконуються в коротких гілках `feature/...`, `fix/...` або `docs/...` і проходять через pull request у `main`. Перед злиттям потрібні перегляд diff, успішні `npm run check` та `npm run build` і перевірка відповідного сценарію. Автоматичні перевірки не замінюють ручної перевірки поведінки й доступності.
