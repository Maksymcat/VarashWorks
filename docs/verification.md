# Перевірка локального каркаса

Дата: 19 жовтня 2026. Середовище: Windows, Node.js 24.19.0, npm 11.17.0.

## Пройдено

- `npm run check`: Biome, генерація типів маршрутів, TypeScript і Prettier.
- `npm run build`: виробнича збірка Next.js 16.4.2 без попереджень.
- `npm ls --depth=0`: прямі залежності відповідають маніфесту.
- Перевірка npm при встановленні: 0 відомих вразливостей. Це стан реєстру на дату перевірки, а не повний аудит безпеки.
- HTTP у виробничому локальному сервері: `/`, `/masters`, `/masters/example`, `/request`, `/for-masters` — 200; `/not-a-route` — 404; `/robots.txt` — 200. На кожній HTML-сторінці один `main` і `noindex`.
- У браузері: Tab відкриває видиме посилання «Перейти до вмісту»; Enter переносить фокус на `main`; клавіатурою відкривається каталог, з нього посилання веде до заготовки профілю.
- Оглянуто каталог у тимчасових iframe шириною 320, 390 і 768 px: мобільні блоки в одну колонку, на 768 px — дві; текст і картки поміщаються по ширині. Оглянуто головну у viewport 1280 px. Тимчасову HTML-сторінку перевірки видалено.
- SHA-256 локального `docs/product-plan.md` збігається з повним вкладенням користувача: джерело збережено без редагування.

## Межі перевірки

Це каркас: даних, фільтрації, обробки `slug`, форм і бекенду немає. Будь-який URL формату `/masters/щось` поки відкриває одну заготовку. Перевірка відсутнього майстра з'явиться разом із логікою пошуку запису.

Віддалений GitHub CI й тестовий деплой не запускалися. Повний WCAG-аудит, перевірка на справжніх телефонах, навантажувальні тести, Core Web Vitals і SEO реального вмісту — наступні етапи. `npm ci` окремо в чистому середовищі не перевірявся; створено й узгоджено lockfile, встановлення виконано через `npm install`.

Локальна технічна перевірка пройдена. B03 цілком ще не закрито: потрібні розбір користувачем та тестове розгортання за планом.
