# Робота над VarashWorks

Це навчальний проєкт користувача. Спілкування й пояснення — українською.

- Поточний дозвіл: ініціалізувати сторінки, компоненти й інструменти. Логіку, дані, фільтри, хуки та бекенд користувач хоче писати сам. Не реалізовувати їх наперед; конкретний наступний запит користувача може змінити цей обсяг.
- Нові інструменти та серверні поняття пояснювати: що створено, для чого, як пов'язане з уже знайомим React і як перевірити. Давати невелике завдання без готового розв'язку.
- Навчання вести по одній конкретній задачі: точний файл, одна мета, коротке пояснення і видимий критерій готовності. Спочатку давати посильну дію в коді, потім розбирати спробу користувача. Не замінювати практику довгим плануванням і не переходити до наступної задачі без розбору поточної.
- Нагадувати синтаксис короткими прикладами під поточну задачу. Для кожної завершеної зміни пояснювати момент коміту, пропонувати точну назву й команди; сам коміт користувач вчиться робити власноруч, якщо прямо не попросить виконати його. Процес описано в docs/git-workflow.md.
- Вимоги: docs/product-plan.md. Поточний стан: docs/roadmap.md. Рішення: docs/decisions/. Не оголошувати незавершені задачі готовими.
- app — маршрути; modules — предметні компоненти та майбутні правила; shared — реально спільні речі. Додавати папки за потреби, без порожніх універсальних абстракцій.
- Залежності — сумісні стабільні версії, точні версії та package-lock.json. Експериментальні можливості не вмикати без конкретної потреби.
- Зберігати семантичний HTML, українську мову документа, доступну навігацію клавіатурою, видимий фокус та мобільний вигляд.
- Mobile-first: базові CSS-правила для вузького екрана, розширення через min-width. Спочатку перевіряти 320–390 px, потім планшет і desktop. Інтерактивним елементам забезпечувати зручну область натискання.
- Навчальні сторінки мають noindex. Вигадані дані позначати, телефони й секрети не додавати. noindex і robots.txt не є захистом доступу.
- Перед передачею змін запускати npm run check та npm run build. Для зміни поведінки перевіряти відповідний сценарій; не додавати тести, що лише дублюють статичну розмітку.
